2.1 交付规划阶段

问题：需求失控——开发中自行添加未确认功能
交付人觉得"这个功能加上更好"，未与用户确认就直接开发，导致交付范围膨胀、验收时出现分歧。
解决方案：只做确认过的需求，新需求先记录、给方案、再确认
  • 新需求先记录到需求清单，给出实现方案，用户确认后才开始做
  • 用户明确说"其他部分一点都不能修改"时，只改指定部分
  • 遇到系统限制，先说明限制，再给替代方案

2.2 交付打包阶段

问题：交付漏件——只发主体文件，其他件被遗漏
只交付运行件，忘了源码包、环境包、文档与源码包。用户换设备、环境重置时找不到东西。
解决方案：九件核销表逐件勾选，缺一件不交付（G4 门禁）
  • 按九件清单逐一生成/复用，文件名逐个核对
  • 编译环境包无变化时复用旧包，但必须列入清单
  • 九件齐 + 命名对 + 文件可访问，才允许进入发布验收

2.3 环境与签名管理

问题：环境重置后无法编译——SDK/依赖靠在线环境存活
编译环境依赖在线工作区的持久性。环境一旦重置，SDK、编译器、依赖全部丢失，重新下载配置耗时数小时。
解决方案：编译环境打包保存 + 一键安装脚本，快速恢复
  • 编译环境包（工具链 + 离线依赖 + 环境说明 + 一键安装脚本）随每次交付打包
  • 环境丢失后按说明快速恢复
  • 假设每次编译前环境都是空的，不依赖任何在线持久性

2.4 多平台与网页部署

问题：网页版本地服务 404——打开页面显示文件不存在
网页版启动本地服务后访问 404，通常是服务默认目录与站点文件实际位置不一致。
解决方案：显式指定站点根目录启动服务
  • 启动命令显式指定站点目录，不依赖默认目录
  • 交付说明中写明启动命令与端口，用户复制即可运行

2.5 质量与验收

问题：编译成功 = 交付完成
只验证"能编译、能安装"，没有做功能与兼容性测试。交付后用户反馈核心功能不显示、跳转异常。
解决方案：G2 四重验证——安装/功能/兼容/回归
  • 安装测试：全新安装 + 覆盖安装 + 图标 + 启动无白屏
  • 功能测试：页面、按钮、数据持久化、核心功能全状态
  • 兼容性测试：多系统版本、多浏览器、多分辨率
  • 回归测试：上次已修复问题不复发，旧功能无退化

2.6 文档维护

问题：文档重写导致历史丢失
每次更新版本历史或避坑指南时整体重写，旧版本信息、历史踩坑记录被删掉，可追溯性归零。
解决方案：增量演进——旧内容零改动
  • 历程网站：新卡片插入最前，更新 latest-card，旧卡片一律不动
  • 本表避坑区：新坑追加到对应小节末尾，旧 problem/solution 不删不改

2.7 交付前检查清单（G1~G4 精简版）

G1 构建门：签名文件路径正确 / 依赖配置存在 / 内部版本号 +1 / 对外版本号更新

G2 测试门：全新安装 + 覆盖安装通过 / 核心功能全流程可走通 / 兼容性抽样通过

G3 文档门：新卡片插入最前且旧内容零改动 / 最新版信息与交付一致 / 下载链接全部有效 / HTML 与源码包同步

G4 交付门：九件清单逐件核销 / 文件名符合命名规范 / 版本号多处一致 / 交付说明已给出 / 用户验收已确认

3.3 决策记录库（ADR）

决策背景与选择
自包含单文件 HTML背景：网页版需要可长期访问、可本地运行。选择：单文件 HTML，无外部依赖。理由：可双击运行、不受隧道/服务失效影响。
编号去圈号背景：交付清单编号曾用圈号。选择：统一改阿拉伯数字（1. 2. 3.）。理由：官方化表述，避免字体兼容与复制歧义。
